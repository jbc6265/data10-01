## 결정과 이유

- **타수는 세 가지 길로 셉니다.** 수강생 샘플 칸에 「프레스 누적 타수」와 「금형 타수」가 함께 있어, 「타수(이 행에서 친 횟수)」 열 → 같은 프레스의 누적 타수 차이 → 같은 금형의 누적 타수 차이 순서로 씁니다. 「금형 타수」는 그 행의 횟수로 읽었습니다(가정, 기획서 10장 4번). 둘 다 있으면 「누적 차이 = 그 사이 타수 합」인지 점검해 어긋난 곳을 보여 줍니다. 누적값이 줄면(카운터 초기화) 그 행은 비웁니다 — 큰 음수가 합계를 망치지 않게.
- **금형 사용 타수 = 시작 시점 사용 타수 + 사용 시작일(교체일)부터 로그 타수.** 로그가 금형의 일생 전체를 담지 않으므로 기준표에 시작값을 둡니다. 「교체 기록」 버튼이 시작일을 바꾸고 시작값을 0 으로 되돌립니다. 오버홀도 같은 구조(마지막 오버홀 뒤 로그 이전 타수)입니다.
- **예정일은 최근 14일 일평균(쉬는 날 포함 달력 일수)으로 추정합니다.** 가동일로만 나누면 실제보다 빨리 닿는 것처럼 나옵니다. 최근에 안 쓴 금형은 예정일을 내지 않습니다.
- **이상 감지는 통계 기준까지입니다(강사 결정).** 고장 이력이 없어 「무엇이 고장 신호인지」 배울 수 없으므로, 채널마다 최근 14일을 바로 앞 42일 기준선과 비교합니다.
  - 기준선은 **중앙값·MAD**(×1.4826) 가 기본입니다. 평균·표준편차는 튀는 값 몇 개에 흩어짐이 크게 잡혀 오히려 둔해집니다(테스트로 확인).
  - **기준선 구간을 최근 구간 바로 앞에 둡니다.** 매일 직전 며칠로 기준선을 다시 잡으면(순수 이동 기준선) 서서히 오르는 추세를 기준선이 따라가 놓칩니다 — 심어 둔 P2 가 바로 그 모양입니다.

- **외부 망·협력사 접속.** 정적 페이지라 GitHub Pages 주소는 외부에서 열리지만 데이터는 브라우저마다 따로입니다. 협력사가 같은 데이터를 함께 보려면 로그인·권한·공유 DB 가 필요해 2단계(Supabase)로 두었습니다. 1단계에서는 기준표 엑셀·JSON 백업으로 주고받을 수 있게 했습니다.

## 결정과 이유

- **「금형 타수」를 누적 카운터로 바꿨습니다.** 받은 로그에서 0 → 719 로 오르고 교체 때 0 으로 돌아가는 값이었습니다. 1단계는 「그 행에서 친 횟수」로 가정했었습니다(기획서 10장 4번). 하루 타수 칸은 「타수」라는 이름으로 계속 읽습니다.
- **σ 기본값은 표본 표준편차.** 교과서의 개별값 관리도(I-MR)는 MR̄/1.128 을 쓰지만, 받은 로그의 앞뒤 값 상관이 전류 0.96·온도 0.99 라 이동범위가 매우 작습니다. 처음 1시간 기준으로 재 보니 이동범위 방식은 온도 3,425점·전류 2,520점이 관리선 밖, 표본 표준편차는 0점이었습니다. 두 방식 모두 고를 수 있게 하고 이유를 화면에 적었습니다.
- **추가 규칙(연속 9점 등)은 기본 끔.** 같은 까닭으로 2초 값에선 전류 3,600점 중 3,086점이 「연속 9점 한쪽」에 걸렸습니다. 1분·5분 평균으로 묶어 보는 보기를 두어, 묶은 값에서 켜 보게 했습니다(샘플 P4 전압 0.3V 내려앉음은 1분 평균에서만 또렷함).
- **2초 원값은 정상이어도 ±3σ 를 우연히 넘습니다(370점에 1점, 약 12분에 한 번).** 이어진 이탈점은 한 번(사건)으로 묶어 목록을 짧게 했습니다.
- **정지 구간 값은 관리도에서 뺌(기본).** 정지하면 전류가 공회전 값으로 떨어져 늘 LCL 밖으로 나옵니다. 정지 판정은 「앞 타수와 뒤 타수 사이가 60초(6사이클)를 넘는 구간」입니다.
- **기준 구간은 「처음 N개(1,800개 = 1시간)」가 기본, 보는 구간과 따로.** 「최근 10분」을 보더라도 관리 한계는 기준 구간에서 잡습니다(그렇지 않으면 보는 구간이 바뀔 때마다 한계가 따라 움직여 관리도가 아님).
- **큰 파일은 4MB 조각씩, 조각마다 화면에 양보.** 웹 워커는 `file://` 로 열 때 막히는 브라우저가 있어 쓰지 않았습니다. 행은 바로 타입 배열 묶음으로 쌓아 메모리를 줄였습니다(17만 행 ≈ 수 MB).
- **그래프는 600칸으로 줄이되 이탈점은 줄이지 않습니다.** 칸마다 최소~최대 세로줄 + 평균선. 이탈점이 2,000개를 넘으면 칸마다 가장 먼 점 하나만 그리고 그렇다고 적습니다.
- **2초 로그 → 하루 묶음.** 프레스·날짜·금형마다 한 행(타수 합, 정지·끊김을 뺀 가동 시간, 정지 아닌 값의 평균)으로 기존 기록에 넣어, 금형 수명·오버홀·「최근 14일 vs 앞 42일」 판정·월별 보고서가 그대로 이어집니다. 같은 날을 다시 넣으면 그 프레스의 하루 묶음을 새로 만듭니다.
- **「최근 N분」은 로그 마지막 시각 기준.** 지금은 파일을 넣을 때마다 갱신되는 구조라 「지금 시각」 기준이면 빈 화면이 됩니다.
